# Каталог товаров PRESSOVAC

## Предпочтительный способ работы

- Выполняй изменения каталога через GitHub-репозиторий: код, данные товаров, описания, изображения, цены и поведение корзины должны быть оформлены в репозитории.
- Не предлагай отдельную ручную работу в Supabase и не проси пользователя добавлять товар в Supabase самостоятельно. Тот факт, что приложение сейчас читает существующие товары из Supabase, сам по себе не означает, что для нового товара требуется отдельная работа в Supabase. Сначала реализуй репозиторное решение и подключи товар в коде приложения.
- Если после проверки архитектуры репозиторный способ действительно не может выполнить задачу, используй Lovable как запасной путь. Пользователь разрешил этот путь с Publish при такой необходимости. Не выбирай Supabase как отдельный обходной маршрут.

## Выполнение

- Проверяй фактический источник списка товаров и интегрируй новые записи так, чтобы управление ими оставалось в репозитории.
- Сохраняй существующие идентификаторы и URL товаров. Новым товарам назначай новые стабильные идентификаторы и slug, не пересоздавая старые.
- Не выдумывай цены, артикулы, характеристики, комплектацию или наличие. Если поле не предоставлено, используй только согласованное поведение для отсутствующего значения.
- Сохраняй область Preview, которую запросил пользователь. Обычную работу в репозитории не приравнивай к публикации на боевой сайт. Если задачу объективно невозможно выполнить через репозиторий, применяй разрешённый пользователем запасной путь Lovable с Publish.
- При добавлении позиции без цены не показывай нулевую цену. Реализуй согласованный сценарий корзины и оформления заказа без ложной суммы.
- Перед изменениями каталогов сверяй пользовательские материалы с предоставленными источниками и сохраняй различия между характеристиками моделей.
